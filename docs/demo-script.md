# Demo recording guide

## Hackathon: target 6 minutes 40 seconds

Use a fresh demonstration database and four separate browser profiles. Prepare the driver/loader at 390 px width and dispatcher at desktop width. Do not expose a real environment password in a public recording.

| Time | Show | Explain |
| --- | --- | --- |
| 0:00-0:30 | Four-role workflow and challenge | Three brands share constrained capacity. The product makes every handoff accountable. |
| 0:30-1:00 | Store places an order | Server acknowledgment and eligible date; ambient/chilled orders remain separate. |
| 1:00-2:10 | Generate February 14 draft; expand a trip; open deferral alternatives | Both load limits, receiving margins, fuel, validated choices and honest rejection reasons. Record the repeated-deferral follow-up. |
| 2:10-2:40 | Review all-depot totals, confirm publication; inspect next-run queue | Publication shares the plan and carries deferred demand forward with its identity and history. |
| 2:40-3:30 | Loader flags damage; dispatcher records replacement; loader rechecks | A real failure crosses roles. The driver cannot depart before all checks. |
| 3:30-4:50 | Driver offline, start/arrive, capture proof, reload offline, reconnect and sync | Wait for the saved acknowledgment before reloading. Proof survives; retry is idempotent. Show session recovery or a prepared conflict if time permits. |
| 4:50-5:20 | Store views proof and confirms | Driver evidence is separate from store acceptance. |
| 5:20-6:00 | Architecture/data model and test commands | Next.js, PostgreSQL transaction, version check, command receipt, IndexedDB outbox and service worker. |
| 6:00-6:40 | Peak/workshop scenario and tradeoff | Availability is real; explainable greedy allocation with validated alternatives is not a claim of global optimality. End with the AI disclosure. |

## Designathon: target 4 minutes

0:00-0:40: state the fragmented-handoff problem and chosen scope.
0:40-1:20: four personas, their device/context differences and the connected flow.
1:20-2:10: planning, deferral decisions and why both load limits matter.
2:10-3:20: fully developed offline-proof degradation journey and conflict recovery.
3:20-4:00: explain prioritization, visual consistency, central tradeoff and AI disclosure.

Use the actual high-fidelity design/prototype. Upload as unlisted YouTube videos and submit the links with the required phase artifacts. This repository does not upload or submit on the team's behalf.
